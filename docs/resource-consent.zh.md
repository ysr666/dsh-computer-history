# 网站与工作区授权（Issue #96）

Computer History 默认把活动元数据保存在本机 SQLite，但“本地存储”不等于可以不经同意扩大记录范围。

## 设置 → 数据与隐私

**允许记录的网站**、**允许记录的编辑器工作区**分别有三种模式：

- **全部**：保留已有的应用级授权语义，升级后不会悄悄改变旧用户的采集范围。
- **仅限允许列表**：只记录明确列入的浏览器网站源站或经过编辑器伴侣背书的工作区根目录。名单为空时不记录该类型的新活动。
- **全部不记录**：不记录该类型的活动。

应用本身必须先被允许。内置受保护路径、显式 deny/protect 规则始终优先。网站和工作区授权互不影响，也不影响普通文件/终端采集。

网站必须填写完整的 HTTP(S) 源站（例如 https://github.com），协议、域名、端口都参与判断；其他子域名或仿冒域名不等于同一源站。不接受 URL 路径、查询参数、身份凭据和片段。浏览器伴侣仍会先过滤查询参数和片段。

编辑器填写绝对工作区根目录。Windows 路径不区分大小写进行规范化，POSIX 路径保留大小写。选择严格名单后，必须由配对的编辑器伴侣背书根目录；无法背书的原生 Accessibility/UIA/AT-SPI 编辑器观测会被拒绝，即使路径看起来位于允许目录下。严格模式请搭配编辑器伴侣使用。

## 升级与审计约定

新授权保存在原来带版本号的 policy_rules 表中，以 @dch-consent/v1/ 私有命名空间和精确匹配区分类型，不需要升级数据库结构。旧的无类型 resource allow 不会突然变成新的采集授权。旧用户升级后两类模式默认显示“全部”，维持原有应用授权行为。

变更经由已有鉴权的策略 API 提交，只替换对应类别的标记，保留内置及其他类别规则，仅影响之后写入的活动。审计预览使用相同的判断函数。**修改授权不会自动清除历史数据**，如需删除，请到“数据 → 删除历史”单独操作。

记录授权与远端模型摘要、DSH Agent Continue 发送上下文的授权互相独立。

验证：tests/unit/resource-consent.spec.ts 和 Companion 集成测试覆盖名单执行、原生采集绕过、保护/拒绝优先、Windows 路径、API 规则验证、旧数据兼容。
