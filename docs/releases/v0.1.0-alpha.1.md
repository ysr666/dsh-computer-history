## What this alpha is

`dsh-computer-history` is a privacy-first work-continuity plugin for DeepSeek Harness.
It turns local activity metadata into deterministic **Work Episodes** so an agent can answer
"What was I working on?" and selectively continue from useful context without recording the
contents of the screen.

## Highlights

- **Local-first history.** Recent evidence is stored in local SQLite; no remote history service is required.
- **Metadata-only boundary.** The design excludes screenshots, screen recordings, keystrokes,
  clipboard contents, terminal output, source-file bodies, browser page bodies, Accessibility
  text values and selected text.
- **Work Episodes and resume context.** Observations are grouped deterministically and exposed
  through the authenticated Host API and agent-scoped tools.
- **Explicit privacy policy.** Capture starts off, application access is include-only, and
  protected or uncertain surfaces fail closed.
- **Three collector targets.** macOS uses Accessibility, Windows uses UI Automation, and Linux
  uses AT-SPI. The shared protocol is exercised across all three in CI.
- **Public-project polish.** Timeline Orbit branding, localized plugin metadata, privacy-aware
  issue templates, private vulnerability reporting, secret scanning and push protection are
  in place.

See `docs/release.md` for the exact DSH/profile and measured evidence.

## Known alpha limitations

- No stable compatibility promise yet.
- Browser/editor companion behavior depends on their own install and pairing paths.
- Linux desktop-bus availability and desktop permissions vary by environment.
- Rollback across a database migration requires a matching store backup or a fresh data directory.

## Before publishing

1. run `pnpm verify`;
2. run `pnpm verify:release:blockers`;
3. change `package.json` from the `-dev` version to `0.1.0-alpha.1`;
4. add a matching `## 0.1.0-alpha.1` section to `CHANGELOG.md`;
5. run the release preflight against the assembled artifact;
6. only then create tag `v0.1.0-alpha.1`.

The tag-driven workflow will build and verify the artifact and create the GitHub release.
