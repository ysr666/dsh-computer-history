# Computer History v1.1.0 — release candidate notes

**Status: NOT RELEASED.** This is a review draft only. Do not create a
`v1.1.0` tag or run npm Trusted Publishing without an explicitly approved
release decision and a green CI run on the exact candidate commit.

Computer History v1.1.0 extends the Continue-first v1.0 series with
**evidence-backed Work Memory, bounded history retrieval, contextual
continuation, and advisory workflow suggestions**. It does not promise
access to files or data that the collectors never observed.

## What is new

- **Work Memory (M1):** Read-only project reconstruction and retained
  provenance, using trusted Work Thread identities.
- **User-confirmed long-term notes (M2):** Explicitly saved/edited/deleted
  local notes with a separate backup restore flow. Retention and Forget
  boundaries remain distinct; AI note access requires its own scoped grant.
- **Ask Your History (M3):** Natural language-oriented, source-linked history
  exploration that never substitutes speculation for missing observations.
- **Work Thread Intelligence (M4):** Conservative cross-app evidence
  suggestions. Exact canonical file sharing remains advisory, and temporal
  neighbours stay **unattributed**, never silently merged into Continue.
- **Contextual Continue (M5):** Optional same-session M1/M4 history depth,
  bound to an existing Continue session. No change to Continue selection,
  Work State target order, or first-turn injection.
- **Suggested Skills (M6):** Detect recurrent retained activity with at least
  three distinct Episodes across two days. These are **candidate patterns**,
  not safe executable Skills or generated commands.
- **Suggested Automations (M7):** Identify narrow test/build date rhythms
  and offer copyable, user-reviewed reminder **drafts**. No job is created,
  scheduled or run; frequency, time, location and permissions remain the
  user's decisions.

## Security and migration

- Host normalization no longer persists free-form browser page titles
  that can echo URL query secrets. Browser URL credentials, query strings
  and fragments are stripped before storage.
- **Migration 0015** removes legacy browser titles and normalizes retained
  URL identities, safely merging duplicates while preserving citations.
- Importing older JSON backups also re-sanitizes browser metadata and
  recomputes newly imported browser Episode summaries. Previous exports
  produced by old versions may still contain sensitive data and must be
  treated as such.
- No new default capture scope, automatic remote AI disclosure, model call,
  background job or permanent cross-project identity inference.

## Important limitations / user actions

- **Not compatible with the owner's current DSH 0.1.2-rc.1 desktop profile**
  without a separately tested CLI/runtime upgrade. Verified DSH variants
  include `0.2.0-rc.2` and `0.2.1-alpha.2`, not arbitrary future alphas.
- The existing SQLite history cannot be backed up reliably by copying
  `history.sqlite` while a WAL/SHM is present. Follow
  [the read-only upgrade preflight and restore plan](../upgrade-v1.1-preflight.md)
  before authorizing any live migration.
- Real populated multi-project suggestion quality and safe user-level
  backup/rollback are distinct acceptance gates; synthetic and one-Episode
  product checks do not prove all user histories will yield useful Skills.
- No installer or automated scheduler should be enabled merely because
  an M6/M7 candidate is displayed.
