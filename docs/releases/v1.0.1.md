# Computer History v1.0.1 — Alpha 2 compatibility candidate

**Status: not published.** DCH v1.0.0 remains available and unchanged on npm and GitHub.

## Changes

- Explicitly support **DSH `0.2.1-alpha.2`** along with the previously verified **`0.2.0-rc.2`** Host. Cordis `4.0.5-alpha.1` is accepted only as a specifically tested prerelease.
- Keep the exact, evidence-backed Continue/Episode/Work State behavior, privacy defaults, editor/browser companion opt-in, native binary selection and local data retention.
- Verify an isolated Alpha 2 Mac Host with a real DSH Web App, real Chrome, native Continue, Browser Companion privacy matrix, and installed-plugin lifecycle.

## Compatibility and testing

The new Alpha 2 branch was tested on macOS. Windows and Linux platform-native collectors continue to use the three-platform packaged build/install checks; this does **not** claim the Alpha 2 desktop Host was tested on those platforms.

Alpha 2's newly published dependencies may lag on third-party npm mirrors. In a **throwaway testing profile**, use the official npm Registry. This Alpha may also prompt pnpm 11 to approve the `koffi` native build; only enable it if you trust the source and need the corresponding DSH Web App. The project's end-to-end test targets its temporary profile, and never modifies user-level npm settings or existing DSH profiles.

The published v1.0.0 tarball was used for the initial Alpha 2 Host runtime regression, and the revised v1.0.1 manifest is verified separately. The package is only a release candidate until a dedicated reviewed, green, immutable-SHA release publishes it.

## Installation after publication

```bash
dsh plugin --profile <profile> add dsh-computer-history@1.0.1
```

Do not use this version number until the npm Registry and GitHub Release both report it.

See [v1.0.0](v1.0.0.md) for privacy and data-security limitations; those restrictions remain unchanged.
